PROMPT 0, CONTEXT (paste first in every new Cursor chat)
I am building solana_blinks, a Flutter package that renders Solana Actions and Blinks as native widgets, similar to Dialect's Blinks SDKs for React and React Native. It targets the Solana Actions spec: GET returns an ActionGetResponse with icon, title, description, label, disabled, error, and links.actions with label, href, type and parameters. POST with a JSON body containing account returns an ActionPostResponse with a base64 transaction, an optional message, and optional links.next for chaining. Use Dart 3, null safety, sealed classes for results, and no code generation. Keep the pure-Dart core free of Flutter imports. The wallet must always sit behind my own BlinkWalletAdapter interface, never called directly from widgets. Use the existing pub.dev packages solana, http and solana_mobile_client. Do not reimplement cryptography or the mobile wallet protocol.

PROMPT 3, ACTION CLIENT
In lib/src/core/action_client.dart, create an ActionClient that wraps an injectable http.Client. Add three methods. fetchAction(Uri) does a GET with Accept application/json and returns ActionGetResponse. resolveHref(String href, Map<String,String> values) fills curly-brace template parameters like {amount} with URL-encoded values and resolves relative hrefs against the action's origin. postAction(Uri, String account) POSTs JSON with the account field and returns ActionPostResponse. Add followNext(ActionPostResponse, String signature), which for a post next link POSTs account and signature to the callback href, and for an inline next link returns the embedded ActionGetResponse. Map non-2xx responses with a message field into a typed BlinkException. Add a timeout and a configurable User-Agent. Write tests in test/core/action_client_test.dart using http's MockClient for success, error JSON, template substitution, relative hrefs, and both chaining types.

PROMPT 4, WALLET ADAPTER INTERFACE
In lib/src/wallet/blink_wallet_adapter.dart, define an abstract class BlinkWalletAdapter with: a Future<String?> connect() that returns the base58 public key; a String? get publicKey; Future<void> disconnect(); Future<List<Uint8List>> signTransactions(List<Uint8List> transactions); and Future<List<String>> signAndSendTransactions(List<Uint8List> transactions) that returns base58 signatures. Add a bool get supportsSignAndSend and a sealed WalletException hierarchy covering user rejected, not connected, no wallet installed, and unknown. Document every method, saying this interface is the only boundary between the package and any wallet, so implementations can be swapped. Do not import solana_mobile_client in this file. Create a FakeWalletAdapter in test/helpers/fake_wallet_adapter.dart for tests.

PROMPT 5, TRANSACTION EXECUTION
In lib/src/core/transaction_executor.dart, create a TransactionExecutor that takes a BlinkWalletAdapter and an RPC URL. Add execute(ActionPostResponse response) that base64-decodes the transaction bytes. If the adapter supports sign and send, it calls signAndSendTransactions. Otherwise it calls signTransactions and submits the signed bytes with sendTransaction from the solana package's RpcClient, using base64 encoding. Then it polls getSignatureStatuses until the status is confirmed or a 60-second timeout, and returns a sealed ExecutionResult of success with the signature or failure with the reason. Do not deserialize or modify the transaction. The Action server builds it, and we only pass the bytes to the wallet. Then create lib/src/wallet/keypair_wallet_adapter.dart, a devnet-only KeypairWalletAdapter that implements BlinkWalletAdapter using the solana package's Ed25519HDKeyPair. It signs by reading the message bytes after the signature section of the wire format and writing the signature into the slot that matches its public key. Mark it in the docs as not for production. Write tests with the fake adapter and a mocked RPC.
